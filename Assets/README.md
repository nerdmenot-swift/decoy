# Brand assets

A scarecrow's hat with straw beneath it, and no face — for a library that generates
people who do not exist.

Everything here is generated by `build-logo.py` from computed geometry. **Do not edit
the SVGs or PNGs by hand**; change a ratio in the script and re-run it:

```
python3 build-logo.py        # needs Pillow for the PNG exports
```

One geometry function feeds both the SVG writer and the PNG renderer, so the two
cannot drift apart. Every proportion is expressed as a ratio of the brim width, which
means the mark is rebalanced by changing a number rather than by nudging shapes, and
the straw fan is generated from mirrored angles rather than placed by eye.

## Files

| File | Use |
|---|---|
| `logo.svg`, `logo-{512,1024}.png` | README, docs header, social card |
| `logo-dark.svg`, `logo-dark-*.png` | the same on dark grounds |
| `icon.svg`, `icon-{16,32,48,180,512}.png` | favicon, app icon, package avatar |
| `icon-dark.svg`, `icon-dark-*.png` | dark-ground icon |

The icon is the same drawing with tighter padding and shorter, fatter straw. All PNGs
are transparent — no background is baked in.

## Palette

| | Hex | Role |
|---|---|---|
| Teal | `#328191` | crown and brim |
| Cream | `#F2EDE1` | hat band |
| Amber | `#E0A029` | straw |
| Teal (dark ground) | `#5AAEC0` | lifted; `#328191` is too close to `#0F1216` to hold an edge |
| Cream (dark ground) | `#EDE7DA` | |

Note that the cream band nearly matches a paper background, so on white or `#F8F8F5`
it reads as a gap between crown and brim rather than as a band. That is deliberate and
it looks right, but it means the mark shows a band on coloured and dark grounds and a
gap on light ones. If that inconsistency ever bothers anyone, make the band
transparent and the mark becomes two colours that behave identically everywhere.

## Why the icon keeps the straw

The obvious reduction is to drop the straw for small sizes, on the grounds that five
tapered wedges cannot survive a 16-pixel grid. That was tested, and it was wrong.

What survives at 16px is not the individual wedges but the **amber mass** beneath the
brim — the only colour contrast the mark has, and the thing that makes it identifiable
in a tab strip. Without it the icon is a teal block on a bar, which reads as a shelf.
The blur the reduction avoided cost more than it saved.

Render `sizes.png` from the script if you want to see the comparison again.

## Favicon markup

```html
<link rel="icon" href="/icon.svg" type="image/svg+xml">
<link rel="icon" href="/icon-32.png" sizes="32x32">
<link rel="apple-touch-icon" href="/icon-180.png">
```

Serving the SVG first means modern browsers scale it themselves; the PNGs are the
fallback. `icon-180.png` is the iOS home-screen size, which is not transparent-friendly
on every OS version — put it on `#F8F8F5` if it looks wrong against a home screen.

## Provenance
